# M6: faster opt16, implementation plan

> For agentic workers: subagent-driven development. One implementer per task, a task review after each, and a whole-branch review at the end.

**Goal:** make the L16-class GPU preset faster, using the measured findings of the M6 research round (`docs/superpowers/m6/synthesis.md` and reports a01–a12).

**Approved by the user (2026-10-01):** "do both tracks of 1 to make opt16 faster".

## Global constraints

- Output is standard zstd: one frame per block, at most 64 KiB per block, independent blocks, decodable by libzstd.
- Existing presets stay byte-identical. This covers `lvl3` and every other preset, including today's `opt14`/`opt16`. The lvl3 anchor test and every differential test must pass unchanged.
- The GPU is byte-identical to the CPU oracle for every preset, new ones included.
- Block size is always 64 KiB (user decision, 2026-10-01). No 16 or 32 KiB tests, gates or benchmarks.
- New presets must reach libzstd's ratio on the full corpus at 64 KiB. Measure with `gzc-bench ref` against `gzc-bench cpu` on the same build. libzstd levels are capped at 16.
- WGSL is u32-only, apart from the optional `wgpu_int16` feature, which needs a u32 fallback. A no-subgroup path must remain. Metal, Vulkan, and the shift and vector-store emulation modes must stay correct; `tests/differential_emulated.rs` and `tests/poison.rs` must pass.
- VRAM budget is 6144 MiB, and `vram_bytes` must equal the real allocations.
- **Benchmarking.** All agents share one machine, so use interleaved A/B runs and report ratios. Headline numbers are taken only when no other agent is using the GPU. Track A tasks run one at a time, and Track B0 uses the CPU only.
- `/tmp` is a RAM disk. Put cargo target dirs under `~/.cache` and delete them when done.
- Commits end with `Claude-Session: https://claude.ai/code/session_01C7yssTUPsjdQxYsDW3tGsM`.
- Run commands in the foreground. Implementers do not spawn subagents and do not ask questions.

## Track A: K3opt speed, byte-identical to today's oracle

The tasks run in order because they all edit `crates/gzc-gpu/src/shaders/k3_opt.wgsl` and `k3opt.rs`. Every task must:
- keep all six pass schedules exact against `opt::passes`, including per-pass histograms;
- pass the 4000-block corpus test at 64K;
- re-check registers and shared memory with vkstats on every pass kernel. The hard gate is staying inside one wave at the batch size used.

**A1: register diet, smaller workgroup memory.**
- Sources: a02 I1+I2 (`artifacts/a02-gpu-features/v_pk16.*`, `v_regs*`), a03 v_mlc2/3 (`artifacts/a03-memory/v_mlc*`), and a11 item 2.
- Changes:
  - pack the match records into one word;
  - derive the lane constants;
  - drop epilogue arguments that stay live across the DP;
  - use u16 LL/ML/OF price tables, packed into u32 or `wgpu_int16`;
  - per pass, omit the histogram and fix-up arrays that the pass never touches.
- Fix the private-ring fallback, which v_mlc3 broke.
- Gates: at most ~88 registers on every pass kernel, and workgroup memory at most 4266 B at 64K.
- Expected: −4…−8 % at b2900, and about −30 % at b3586–4080.

**A2: divergence.**
- Source: a01, final kernel `artifacts/a01-divergence/p5.wgsl` and `p5-vs-base.diff`.
- Changes:
  - a rep-length memo: the same offset at p+d gives length L−d;
  - a merged lockstep rep extension, capped at 36, plus an exact tail;
  - a flat phase-2 emit;
  - optionally, grid relaxation for the optLevel-2 pass only.
- Expected: −12 % over the four passes.

**A3: dead-position skip.**
- Source: a09 (`artifacts/a09-data-aware/dead-skip-fold.diff`).
- 61 % of positions have no earlier position sharing their first 3 bytes. Skip these in one step, and fold literal-only positions in the cheap passes.
- Compute the dead-run flag on the GPU, in K2opt or K1. Do not compute it on the host as the prototype did. Count its bytes in VRAM.
- Expected: −10…−13 %.

**A4: persistent heavy-first K3opt.**
- Source: a07 (`artifacts/a07-scheduling/`).
- Workgroups loop and take blocks from an atomic counter, heaviest first. Block weight is the number of positions whose longest candidate is 3..32, computed on the GPU.
- Grid stays n. Recompute `lane` inside the loop so registers stay at ≤ 93.
- Expected: `--batch max` at 3586 goes from about 51 to 31 µs/block. A one-wave batch should be neutral. The model predicts −27…−32 % on 8 GB cards.
- The order is fixed per batch and the output stays byte-identical.

After A4: a headline measurement on a quiet GPU (opt14/opt16 at b2900 and `--batch max`), then a results doc.

## Track B: a 2-pass L16-class preset (new oracle)

**B0: CPU-only ratio study, runs alongside Track A.**
- Combine these levers in a scratch copy of gzc-core, without changing the repo's oracle yet:
  - (a) multi-block frames, each 64 KiB frame split into 2–4 zstd blocks with their own or repeated tables (a10);
  - (b) an h10 chain on every 4th position, depth 16, with h4 depth 8 (a06);
  - (c) in-pass price refresh, 8/16/32 slices (a04);
  - (d) gap3 (a05).
- Pass schedules to test: 2-pass (Prior or BlockInit + 1 cheap + final) and 1.5-pass.
- Full-corpus ratio at 64 KiB against libzstd L16.
- Pick the smallest combination that clears L16 by at least +0.05 % at every size, preferring the cheapest GPU cost. Report the GPU cost of each lever, and also lvl9s12seg + split.
- Deliverable: a decision table, plus the exact parameters for the oracle change.

**B1+ (planned after B0):** implement the chosen combination:
- an oracle and a new preset (today's `opt16` is kept byte-identical);
- K1/K2 for h10;
- K3 for gap3 and refresh, built on top of Track A's kernel;
- a K4/K5 multi-block frame writer.

Gates: byte identity, ratio at all sizes, `--verify`.
