# M4: libzstd level-9 ratio on the GPU — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the GPU zstd compressor reach libzstd level-9 compression ratio (lazy2 over a 4-byte hash chain, 32 deep) on 128 KiB blocks, bit-exact with a CPU oracle, via runtime match-finding presets.

**Architecture:** A runtime `MatchParams` (hashes, min_match, depth, lazy, search_cap) with named presets (`lvl3`, `rung1`, `rung2`, `lvl9`) is defined once in `gzc-core` and used by the CPU oracle, GPU kernels (as injected WGSL constants) and the CLI. The CPU oracle gains a single-hash chain and a port of libzstd's lazy parser. K1/K2 gain a single-hash mode and a depth loop, and K3 gains the lazy parse. Entropy (K5/K4), the frame writer and the pipeline are unchanged.

**Tech Stack:** Rust 1.96 (edition 2024), wgpu 30 / WGSL, zstd 0.14 (libzstd 1.5.7 vendored), existing workspace crates.

**Spec:** `docs/superpowers/specs/2026-09-29-m4-lazy-lvl9-design.md` (normative algorithm in §3). Background: `docs/superpowers/specs/2026-09-29-gpu-zstd-compression-design.md`, `docs/results/2026-09-29-m3.md`.

## Global Constraints

- Every frame must decode with libzstd (`zstd::bulk::decompress(frame, BLOCK_SIZE)`) to the exact padded block.
- GPU frame bytes must equal CPU `write_frame(block, &reference::compress_block(block, params), opts)` for every preset.
- The `lvl3` preset must stay **byte-identical to M3** (anchor hash test, Task 1).
- WGSL uses u32 only. CPU decision logic that the GPU mirrors is integer-only (no floats, no u64 outside bit writers).
- Target GPU: ~8 GB card. Pipeline configs must fit `--vram-budget-mb` (default 6144). `vram_bytes` counts every buffer.
- libzstd benchmark levels: at most 16 (hard). Default sweeps stay 1–6. L7–L9 are allowed as M4 comparison points.
- Tests never read `data/`. `data/` and `out/` are never committed.
- Run tests under default features and `--no-default-features --features gzc-core/block-16k,gzc-gpu/block-16k,gzc-bench/block-16k`.
- libzstd C source (ground truth for the lazy port): `~/.cargo/registry/src/*/zstd-sys-2.1.0+zstd.1.5.7/zstd/lib/compress/zstd_lazy.c` (`ZSTD_compressBlock_lazy_generic`) and `clevels.h`.
- Commit messages end with `Claude-Session: https://claude.ai/code/session_01C7yssTUPsjdQxYsDW3tGsM`.

## Review Focus

1. **`min_match = 4` doubles the maximum sequence count.** `MAX_SEQS` (compressor.rs:30) is `BLOCK_SIZE / MIN_MATCH + 1` with `MIN_MATCH = 5`. With 4 it must be `BLOCK_SIZE/4 + 1` = 32769, which exceeds `0x7F00`, so the **3-byte nbSeq header branch** in both CPU `seqenc` and K4 becomes reachable. Pinned in Task 3 (`nbseq_three_byte_form_roundtrips` on CPU and GPU).
2. **Lazy catch-up near `anchor` and near block start**: backward extension must stop at `anchor` and at offset bounds. Pinned in Task 4 (`catch_up_stops_at_anchor`, `catch_up_at_block_start`).
3. **Deferral chains that run to `PARSE_END`**: `ip+1`/`ip+2` lookups at the last parse positions must not read `best[]` past `PARSE_END`. Pinned in Task 4 (`lazy_near_parse_end`) and Task 5 (GPU differential on `period3`/`exact_block`).
4. **Presets and CLI**: an unknown preset name, or a preset not yet implemented, fails with a clear error and never panics. Pinned in Task 1 (`unknown_preset_is_rejected`).
5. **VRAM accounting per preset**: single-hash presets allocate one chain. `vram_bytes` must match the actual allocation, including the bigger `seqs` buffer. Pinned in Task 3 (`vram_matches_params`).

impl MatchParams {
    pub fn validate(&self) -> Result<(), String>; // min_match 4..=8, depth 1..=64, lazy 0..=2, search_cap 8..=256, Dfast => min_match == 5

    pub fn min_seq_len(&self) -> u32;               // == min_match (bounds sequence count)
}
pub const LVL3: MatchParams  = MatchParams { hashes: Hashes::Dfast,  min_match: 5, depth: 1,  lazy: 0, search_cap: 64 };
pub const RUNG1: MatchParams = MatchParams { hashes: Hashes::Single, min_match: 4, depth: 8,  lazy: 0, search_cap: 64 };
pub const RUNG2: MatchParams = MatchParams { hashes: Hashes::Single, min_match: 4, depth: 8,  lazy: 1, search_cap: 64 };

pub const PRESETS: [(&str, MatchParams); 4] = [("lvl3", LVL3), ("rung1", RUNG1), ("rung2", RUNG2), ("lvl9", LVL9)];

pub fn greedy_parse(block: &[u8], best: &[Match], p: &MatchParams) -> BlockOutput;

pub struct GpuParams { pub matching: MatchParams, pub emit_frames: bool, pub huffman: bool } // `depth` field removed
pub fn gpu_supports(p: &MatchParams) -> bool;       // T1: Dfast && lazy == 0

### Task 4: CPU lazy/lazy2 — port of libzstd `ZSTD_compressBlock_lazy_generic`

**Files:** `crates/gzc-core/src/lazy.rs` (new logic, stub created by T1), `crates/gzc-core/src/reference.rs` (dispatch in `parse`), `crates/gzc-core/src/params.rs` (`cpu_supports` → all presets)

**Interfaces — Consumes:** T1/T2 `Match`, `best[]`, `MatchParams`, `seq::{off_base_for, apply_off_base, Reps}`, `reference::match_len`. **Produces:**

```rust
// lazy.rs
/// Lazy / lazy2 parse over precomputed best[] (spec §3.4). params.lazy ∈ {1,2}.
pub fn lazy_parse(block: &[u8], best: &[Match], params: &MatchParams) -> BlockOutput;
```

Normative behaviour is spec §3.4. Read `ZSTD_compressBlock_lazy_generic` in the vendored `zstd_lazy.c` (noDict path) and port it with these substitutions:
- `searchMax(ip)` → `best[ip]`. If `best[ip].len == search_cap`, extend with `match_len(block, ip, ip - offset)`. A result of `len < min_match` counts as "no match". The offBase of an explicit match is `offset + 3`.
- `MEM_read32` equality checks at positions that could read past `BLOCK_SIZE` are replaced by bounded compares: `match_len(...) >= 4`.
- `ilimit` is `PARSE_END`. `best[]` is only valid for `ip < PARSE_END`, so deferral stops when `ip + 1 >= PARSE_END`. Mirror zstd's `while (ip < ilimit)` loop structure.
- `offset_1`/`offset_2` are the M3 `Reps` (`reps[0]`, `reps[1]`). Sequences are stored through the same `off_base_for` / `apply_off_base` bookkeeping as `greedy_parse`, so the frame writer is unchanged.
- Catch-up (backward extension) and the immediate `offset_2` repcode loop are exactly as in zstd.
- Every intentional deviation from libzstd gets a `// deviation:` comment.

- [ ] **Step 1: Failing tests.** In lazy.rs, most using hand-built `best[]` plus blocks so each gain rule is hit exactly:
  - `lazy_prefers_later_longer_match` (step-1 gain strictly greater → defer).
  - `lazy_keeps_on_gain_tie` (step-1 gains equal → keep the current match).
  - `lazy2_second_step_threshold` (+7 boundary: one case wins by 1, one ties).
  - `lazy_rep_check_at_ip_plus_1` (×3 rule).
  - `catch_up_stops_at_anchor`.
